## Question

Implement the decision of cssints-cmgv. Blocked by cssints-wigi, which also edits types.ts and macro.ts.

- [x] `flex(...parts)` with arguments is the `flex` property, checked by the grammar; `flex()` without arguments stays the context with its chain. The same for `grid`
- [x] Types: overloads on `flex` and `grid` (no argument gives `Chain<...>`, parts give `Style` with `Valid<"flex">`); members generator and JSDoc
- [x] `container` stays the condition; docs say the property is written as `containerName`/`containerType`
- [x] Fixtures, type tests, docs/API.md; the demo uses `flex("1")` once

## Summary of Changes

`flex(...parts)` and `grid(...parts)` with at least one argument are now the `flex` and `grid` properties, checked by the grammar (a bare number is a `<number>`: `flex(1)` is `flex: 1`); `flex()` and `grid()` stay the chaining contexts. lib.ts `toDecls` and macro.ts `member` tell them apart by the argument count. Types: a generic `Layout<P, M>` interface in types.ts holds the two overloads (`Chain<M>` and `Style` checked with `Valid<P>`); members.ts declares `flex` and `grid` with it, with the property's grammar/BCD JSDoc (generated by scripts/members.ts). Declaring the overloads inline in the generated file cost +17% instantiations in bench/unused.ts (the file is checked as source); the generic interface costs under 1%. `container` stays the condition; docs/API.md says the property is written `containerName`/`containerType`. Fixtures shorthand, shorthand-bad, shorthand-chain; type tests in test/types/chain.ts; demo uses `flex("1")`.
