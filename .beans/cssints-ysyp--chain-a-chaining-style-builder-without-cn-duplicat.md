A chaining builder as a separate export from `css`: `import { chain } from "cssints"` and `chain().flex().bg("red")` builds one style with no `cn()`. Every property is a method; `.flex()` / `.grid()` with no argument set display and keep chaining, with parts they are the property. Setting the same property twice in one chain is a type error (the method is gone / takes never), so the later-wins rewrite of cn() cannot be written by accident; shorthand over longhand stays legal (the sheet orders it).

## Summary of Changes

- **Instrument: no change.** A site root is any binding of an import `with { type: "cssints" }`, and `rootIdent` walks the callee back through calls and member expressions, so `chain().flex().bg("red")` is one maximal call replaced by its class string (`test/fixtures/chain.ts`: `"_1s47490 _1dahwue"`). Only `chain` went into `named` (macro.ts), which the import rewrite reads.
- **Runtime** (`macro.ts` `chainStep`): `toDecls(name, args)` for every member, so `.flex()` with no argument is `display` and `.flex(1)` is the `flex` property; declarations appended through `merged()` (the later property wins, overlap without containment is still an error) and `carried()` keeps kernels, markers and plugs. `css.flex()`/`chainDecl` untouched; a member that is not a property is refused with `chain() has no .hover()`.
- **Types** (`src/chain-members.ts`, generated by `scripts/members.ts`: 547 members): each property is a method returning `this & { <the property's names>: never }`. `this` is the polymorphic receiver, so the used set accumulates with no mapped type per step; a used name is `never`, so the second call is `This expression is not callable. Type 'never' has no call signatures.`. `.flex()`/`.grid()` with no argument use a conditional rest parameter (`[display: never]` once display is set), so a second display context errors while `.flex().flex(1)` stays legal.
- **Duplicate rule: by property.** `bg`/`backgroundColor` and `p`/`padding` mark each other in either order; a shorthand and its longhand stay legal (`p` then `paddingLeft`, `bg` then `background`), the sheet orders them as for `cn()`.
- **Cost**: import floor +~6.7 k instantiations (`bench/unused.ts` 46 297 → 53 029); 12 chains of five properties 273 741 (tsc) against 264 798 for the same 60 declarations as `cn()` (+3.4 %); `bench/budget.json` re-baselined for `unused.ts` and `plugins-defs.ts`, `bench/chain.ts` added; editable latency in the worktree: first diagnostics 1.9 s, an edit 0.76–1.2 s, hover 125–409 ms.
- **Tests**: `test/chain.mjs` (one site, cn()/condition/media/cv/function/runtime-cn/keyframes, duplicate merge, overlap and unknown-method errors), `test/types/chain.ts`, `docs/API.md` "chain()", wayfinder entry, changeset (cssints minor).

## Engine gaps

None: the instrument already treated a bare imported root as a site root. The one limit is the import floor: the second 547-member member list is checked whenever `cssints` is imported, whether or not a chain is used.
